# Personio integration

Employer-enabled anonymous XML, using the documented [.com/locale workflow](https://support.personio.de/hc/en-us/articles/207576365-Integrate-jobs-from-Personio-into-your-website-via-XML) and [.de XML schema](https://developer.personio.de/docs/retrieving-open-job-positions). No recruiting API token or employer account is used. Depends on the preceding UI, adapter, SmartRecruiters and Workable PRs.

One explicit `en` locale per registered employer avoids fetching duplicate translations. `.de`/`.com` and locale are retained in feed/application URLs and cache keys. Repeated position IDs merge locations and keep one card. Primary/additional offices feed the existing country matcher. Explicit hybrid/onsite labels are excluded from remote-only searches; unknown eligibility stays unknown. XML `createdAt` is not documented as publication, so these cards show Checked only. No language requirement is inferred from the chosen XML locale.

The Worker-safe reader uses no Node, DOMParser, DTD, network entity resolution, or new dependency. It handles CDATA, five XML named entities, decimal/hex character references, comments, quoted attributes and nested text. It rejects malformed documents, disabled/HTML payloads, custom entities/DTDs, multiple roots, invalid characters and unexpected root shapes. Bounds: 2 Mi characters, 50,000 nodes, depth 32, 100,000 tokens, 2,048-character tags, and 1,000 positions. A position cap/invalid public position reports partial coverage; unsafe or incomplete documents report unavailable. Shared response/request/deadline/cache/rate-limit controls still apply. There are no per-job detail requests or locale fanout.
